How it is built: fictional people are created in the local auth shim (the one privileged step); then, as the real actors, the PM creates each project, adds members,
imports the generated CSVs through `stage_import -> build_import -> activate_version`; Site Engineers file claims / corrections / withdrawals / clarification answers
and Supervisors decide them through the domain services; issues and root causes follow. No ledger row is inserted directly.
Determinism: fixed ids for people and projects, fixed anchor date, no clock, no randomness (hash-derived choices). Internal row UUIDs of imported and executed rows
are generated by the database, so reproducibility is defined over external identifiers (`digest()` hashes the business content keyed by activity / resource ids).
Business dates are historical; row timestamps (`created_at`, `decided_at`) are the time the seed ran.

## Commands
```bash
scripts/db_v2.sh up                                   # local PostgreSQL 15/16 cluster + migrations (isolated; Data API off)
export DB_V2_URL="$(scripts/db_v2.sh url)"            # a LOCAL setuai_v2_* database; the API and the seed refuse anything else
export SUPABASE_JWT_SECRET="<a local secret of 32+ characters>"
python3 scripts/seed_v2.py                            # seed an EMPTY database (re-running verifies and changes nothing)
python3 scripts/seed_v2.py --verify                   # read-only invariants + content digest
python3 scripts/seed_v2.py --report [--json]          # per-project counts
python3 scripts/seed_v2.py --reset-local              # empty THIS local database, then seed
uvicorn backend.v2.app:app --port 8020                # API; docs at http://127.0.0.1:8020/docs
TOKEN=$(python3 scripts/v2_dev_token.py rohit.menon)  # local dev token for a seeded person
curl -H "Authorization: Bearer $TOKEN" http://127.0.0.1:8020/api/v2/projects
```

## Known limitations and deferred work (Phase 4 and later)
* The frontend integration is documented separately in `docs/V2_FRONTEND.md`; the legacy demo UI and database are untouched.
* Extraction covers CSV, XLSX, text and text-layer PDF only. Scanned / handwritten documents, photographs and voice need OCR / vision / speech and are Phase 4. Live LLM
  extraction does not exist in the v2 code; there is nothing to switch on.
* Splitting one claim across the children of a split activity (`claim_activity_splits`) is not implemented; nothing is allocated automatically.
* Planned progress and SPI are linear approximations (labelled as such on every payload); there is no CPM time-phased plan and no cost-based earned value.
* The evidence store is a local-disk adapter; a hosted object-storage adapter is future work. File validation is not malware scanning.
* XER and MS Project XML are supported on the committed fixtures and synthetic exports only; no real-world P6 / MSP export has been validated. Native `.mpp` is not supported.
* The seed's row timestamps are the run time; only business dates are historical.
* Notifications are stored and listed through the API; there is no email / push delivery.
